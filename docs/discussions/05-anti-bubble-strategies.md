# Discussion 05 · 反茧房不是反推荐——是约束化探索

Date: 2026-05-01

## 引子

讨论 Compass 反茧房机制时被用户挑战："反过头了——艺术生岗位 / 酒保岗位 反推荐没意义。"
这是非常对的反问。我之前的"加随机扰动"方案有个根本盲点——
**没有把"客观可达"和"心理排除"区分开**。无约束的随机扰动本质是把茧房问题换成噪声问题。

## 两种排除

| 排除类型 | 该不该反 | 为什么 |
|---|---|---|
| 客观硬边界（学历/签证/资格证） | 永远不反 | 反了 = 浪费用户时间 |
| 你过去 thumbs-down 过的同类 | 时间衰减后小范围反 | 6 个月前的偏好可能过时 |
| 你从没考虑过但同类人都去了 | **核心反制目标** | 这是真茧房——你不知道自己不知道 |
| 你考虑过但畏难放弃的 | 配合学习路径反 | 工具应该帮你看清"差什么" |
| 完全不相干的领域 | 永远不反 | 那是浪费 |

## 5-tier 可达圈模型

正确的反茧房**约束在用户客观可达圈内**：

```
Tier 0  客观硬边界          ─┐ 绝不反
                              │
Tier 5  完全无关领域        ─┘

Tier 1  核心专业圈           ← 主推（70%）
        你的专业+经验直接对口

Tier 2  邻近迁移圈           ← 反茧房的甜点（20%）
        现有 skill 可直接迁移过去
        例：金融 → 金融科技 PM / 数据分析 / 策略咨询

Tier 3  可学习扩展圈         ← 条件反推荐（10%）
        补 1–2 个 skill 即可进入
        推荐时必须显式标注"差什么"

Tier 4  远距迁移            ← 仅当强信号才反（<5%）
        完全转方向（金融→教育/创业等）
        只在用户最近 thumbs-up 出现这个方向时
```

**关键约束：反茧房 90% 应该发生在 Tier 2，不是 Tier 4**。
"投行 / 工程师 vs 酒保"对应的就是 Tier 1 vs Tier 5——这两层之间不应该有反推荐。

## 反茧房的四层

按"觉知度"递增：

### Layer 1：基础随机扰动（必须有）
- ε-exploration：10% 推送是"刻意不像你偏好"的
- 时间衰减：6 个月前的 thumbs-down 权重要指数衰减
- 多样性约束：top-K 强制覆盖不同公司/不同薪资段

### Layer 2：反向推荐（counterfactual）
不只推"和你喜欢的相似的"，**也推"和你拒绝的反向极的"**：
> "你过去 30 天连续拒绝了 8 个 startup 岗位，全推大公司——但同 profile 的人有 35% 最后去了 startup。"

激进，但**显式承认算法在偏向某一边**——用户会觉得被尊重而不是被操纵。

### Layer 3：元认知镜面（最重要的一层）
**把算法状态本身显示给用户**：

```
你的偏好画像：
  • Role 多样性指数：0.32（低）
  • 薪资带宽：35–55k（窄）
  • 隐性排除模式：从未推过远程 / 从未推过 startup

⚠ 你可能在错过：
  • Remote 岗位（市场量占 38%，你只看到 4%）
  • 50–200 人 startup（你 thumbs-up 率历史是 22%，但最近 6 周 0 推送）
```

用户看到这个，**意识到自己被塑造**，可以选择"重置画像"或"主动加入这个维度"。
**茧房不可怕，可怕的是用户不知道自己在茧房里**。

### Layer 4：跨用户对照（最高层）
"和你 profile 类似的 100 个人，过去 6 个月推送的 role 分布是这样的——
你的分布偏离了 X 个标准差。是你独特，还是算法偏了？"

这个需要匿名集体数据 → 路径二（Discussion 04）。

## Compass 当前实现到了哪层

- ✓ Layer 1：5-tier 配额 70/20/10 是 ε-exploration 的具象化
- ✓ Layer 3：漂移仪表盘 + ToolAssumption（部分实现）
- ⏳ Layer 2：counterfactual recommendation——还没做
- ⏳ Layer 4：跨用户对照——依赖路径二

## 这条 discussion 落地到的 ADR

- ADR-0002 (5-tier 包含 Tier 2 = 邻近迁移甜点 = Layer 1 反茧房具象)
- ADR-0008 (ToolAssumption 暴露 = Layer 3 元认知镜面)
- 未来 ADR：counterfactual recommendation 的设计
- 未来 ADR：跨用户对照协议（依赖路径二）

## 给后来人

设计反茧房机制时**第一个问题不是"怎么反"，是"反到哪个范围内"**。
反到客观不可达的领域是浪费；反到完全相关的核心圈是没用；反到**"你能但你没想过"**那个甜点区——那才是真反茧房。

这个甜点区在 Compass 是 Tier 2。
在你的产品里它是哪个 tier？想清楚再设计。
