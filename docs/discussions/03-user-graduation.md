# Discussion 03 · 用户毕业是成功，不是 churn

Date: 2026-05-01

## 引子

传统 SaaS 的终极 metric 是 retention——churn 越低越好。
但**求职这个事情，用户成功就走**。所以求职软件做不出 retention，飞轮转不起来。

这是 Compass 选择 Reflective Flywheel + 共进化路径的根本动因——**重新定义成功**。

## 旧定义 vs 新定义

| 维度 | 旧 SaaS | Compass |
|---|---|---|
| 成功指标 | DAU / retention / ARR | 用户三个月后对自己的理解比三个月前清晰了多少 |
| 用户流失 | 失败 | **可能是成功**——他不需要这个工具了 |
| 设计取舍 | 让用户离不开 | 让用户用了之后变得更好 |
| 商业模式 | 持续订阅 | 一次性付费 / 开源 / 非营利 |

## 用户毕业的三种形态

**形态 1：找到工作就走**（最常见）
- 用了 6 个月找到好工作
- 接下来 2-3 年不需要 Compass
- 如果跳槽再回来——这是 retention 反例，用户已经"长大了"

**形态 2：内化了反思方法**（更深层）
- 用了一段时间后，养成了"对照 stated vs revealed preference"的习惯
- 不再需要工具——他自己就在做这件事
- 工具的功能"内化"成了用户的认知能力

**形态 3：从用户变成贡献者**（最理想）
- Notion 的高级用户互相教学的形态
- Compass 的 skill 生态（路径三）就是这个目标
- 用户不"流失"——他变成系统的一部分

## 为什么传统 SaaS 拒绝这个定义

商业模式不允许：
- ARR 模型靠续费——churn 让财报难看
- VC 估值看 LTV/CAC——graduation 把 LTV 砍到 1
- 招聘市场看 DAU——graduation 让数字下滑

但 Compass 不需要这些约束（个人本地工具，开源/非营利）—— **不需要 raise** 反而是 graduation 哲学的护城河。

## 但毕业也不是 churn 那么简单

诚实说——**用户突然走人不一定是好事**。区分：

**好的毕业**：用户带走了对自己的清晰理解、内化了反思习惯、可能成为社区贡献者
**坏的 churn**：用户挫败、放弃、感觉没用

二者外观相似（都不再用），内核相反。Compass 应该努力让前者发生、避免后者。
具体策略：
- 离开前的"自我报告"——帮用户具象化"你这几个月学到了什么"
- 邀请贡献——离开的用户最有发言权讨论"什么有用、什么没用"
- 永久免费——回来时门槛为零

## 这条决策的产品后果

- **不**做"7 天活跃推送"
- **不**做"多 N 天没用提醒你回来"
- **不**做激励循环（点点点拿积分）
- **不**做 dark pattern（注销难、订阅默认续费）
- **不**用 retention 作为 OKR

这些"不做"加起来，构成 Compass 区别于商业 SaaS 的姿态。

## 这条 discussion 落地到的具体设计

- Compass 没有"多久没用提醒你"的功能（且永远不会加）
- Reflective Flywheel 的根本目的是"让用户更清楚自己"——不是"让用户依赖我"
- 路径三（skill 生态）是 graduation 的发酵土壤——毕业用户能继续贡献
- 反思层的"漂移仪表盘 + 工具假设"显式让用户看到自己被怎么塑造——避免无觉知依赖

## 给后来人

这是个**反直觉但成立**的姿态：
> 你做的工具的最高荣誉，不是被持续使用，是**把用户用成更好的人之后被取代**。

如果你不能接受这个，做 Compass 这种产品会很难——所有商业 SaaS 的本能都在反方向。
